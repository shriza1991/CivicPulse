# 06 — UX Specification

## Product Shell
Nivaran should look like a modern decision-support product, not a complaint portal.

Avoid:
- generic admin dashboards
- decorative chart walls
- neon/glow styles
- excessive cards
- fake activity feeds
- old civic escalation terminology.

## Screen 1 — Citizen Demand

Primary actions:
- Speak
- Type
- Add evidence
- Add location

Show:
- detected language
- interpreted demand
- confirmation
- submission status.

Do not show:
- fabricated AI confidence
- invented community matches
- invented policy result before processing.

## Screen 2 — Demand Intelligence Map

Hero screen.

Elements:
- country selector
- region selector
- sector filter
- time filter
- hotspot map
- priority legend
- ranked hotspot summary

Map interaction:
click hotspot → open Demand Cluster panel.

## Screen 3 — Priority Queue

Questions answered:
- What should we examine first?
- Where?
- What category?
- Priority score?
- Population affected?
- Investment context?

Rows should be scannable, comparable and evidence-linked.

## Screen 4 — Recommendation Detail

Sections:
1. Recommendation
2. Priority score
3. Factor breakdown
4. Citizen demand evidence
5. Population context
6. Infrastructure gap
7. Existing investment
8. Unknowns
9. Gemini rationale
10. Human decision controls

## Screen 5 — Policy Brief
Produce a clean, professional policy-oriented artifact.
Do not imply legal authority or approved government action.

## Visual Style
- clean
- professional
- high information density without clutter
- accessible
- strong typography
- restrained motion
- map-centric where useful
- consistent terminology.

## Role UX
Citizen, planner, auditor and admin must not receive the same primary dashboard.
Navigation is role-specific.
